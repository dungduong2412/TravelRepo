## 3. Zod 4 compatibility changes

Zod 4 requires a transformed schema's default to match its output type. The transaction `orphan_only` default changed from input string `'false'` to output boolean `false`; runtime behavior is unchanged.

Zod 4's `uuid()` now rejects legacy SQL Server GUIDs whose version bits are not RFC UUID versions. The sealed snapshot contains valid 8-4-4-4-12 GUID-shaped merchant, collaborator and category identifiers with those historical values. Legacy-capable business identifiers therefore use `z.guid()` while Auth IDs and new media/request IDs remain strict UUIDs. The real imported category-ID regression now passes.
